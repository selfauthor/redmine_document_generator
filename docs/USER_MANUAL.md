# Руководство пользователя Redmine Document Generator

## Введение
Этот плагин позволяет создавать документы Word и Excel на основе шаблонов, заполняя их данными из выбранных задач Redmine. Шаблоны создаются в обычных программах Microsoft Word или Excel с использованием специальных маркеров.

## Создание шаблона Word (.docx)
1. Создайте новый документ в Microsoft Word.
2. Вставьте маркеры шаблона в нужные места (например, `<%Тема%>`).
3. **Важно:** Не разрывайте маркер переносом строки или изменением формата внутри него. Word может разбить текст на несколько скрытых XML-узлов, но плагин автоматически попытается это исправить (нормализация). Для надёжности вводите маркер как сплошной текст.
4. Сохраните файл как `.docx`.

## Создание шаблона Excel (.xlsx)
1. Создайте таблицу в Excel.
2. Разместите маркеры в ячейках. 
3. Для повторяющихся строк (список задач) используйте маркеры `<%BEGIN_ROW%>` в начале строки и `<%END_ROW%>` в конце строки. Плагин размножит эту строку для каждой задачи в выборке.
4. Сохраните файл как `.xlsx`.

## Язык шаблонов

Все команды заключаются в конструкцию `<% ... %>`. Имена полей чувствительны к регистру только в функциях, но сам поиск по контексту выполняется без учёта регистра.

### 1. Базовые поля задачи
Подставляют значение поля текущей задачи.
- `<%ID%>`, `<%Тема%>`, `<%Описание%>`, `<%Статус%>`, `<%Приоритет%>`
- Пользовательские поля указываются по их названию: `<%Сложность%>`, `<%Срочность%>`.
- *Примечание:* Если имя пользовательского поля совпадает со стандартным, приоритет имеет стандартное поле.

### 2. Связанные сущности
- **Родительская задача:** `<%Parent.Тема%>`, `<%Parent.Статус%>`
- **Подзадачи:** Используйте блок `<%BEGIN_SUBTASKS%>` ... `<%END_SUBTASKS%>`. Внутри блока используйте префикс `Subtask.`: `<%Subtask.ID%>`, `<%Subtask.Тема%>`.
- **Наблюдатели:** Блок `<%BEGIN_WATCHERS%>` ... `<%END_WATCHERS%>`. Внутри: `<%Watcher.Имя%>`, `<%Watcher.Email%>`.
- **Связи задач:** Блок `<%BEGIN_RELATIONS%>` ... `<%END_RELATIONS%>`. Внутри: `<%Relation.Тема%>`, `<%Relation.Тип%>`.
  - *Фильтрация по типу связи:* `<%BEGIN_RELATIONS:blocks%>` (выведет только задачи, которые блокирует текущая).

### 3. Условная логика
Позволяет скрывать или показывать части документа в зависимости от данных.
```text
<%IF(Статус == 'Закрыт')%>
  Задача выполнена.
<%ELSE%>
  Задача в работе.
<%END%>
```
- Поддерживаются операторы `==` и `!=`.
- **Специальная проверка на пустоту коллекций:** `<%IF(NOT Subtasks)%>` (истинно, если у задачи нет подзадач). Аналогично для `NOT Watchers` и `NOT Relations`.

### 4. Группировка и агрегация (в основном для Excel)
- `<%GROUP_BY:Статус%>` — задаёт поле для группировки первого уровня.
- `<%GROUP_BY_2:Приоритет%>` — задаёт поле для вложенной группировки второго уровня.
- `<%GROUP_HEADER%>` / `<%GROUP_HEADER_2%>` — начало строки заголовка группы.
- `<%GROUP_FOOTER_2%>` / `<%GROUP_FOOTER%>` — начало строки итогов группы.
- `<%END_GROUPS%>` — обязательный маркер конца области группировки.

**Агрегатные функции** (работают внутри групп или блока `<%BEGIN_TOTAL%>` ... `<%END_TOTAL%>`):
- `<%sum(Оценка времени)%>`, `<%avg(Оценка времени)%>`, `<%min(Оценка времени)%>`, `<%max(Оценка времени)%>`
- Общие итоги по всей выборке: `<%total_sum(Оценка времени)%>`, `<%total_count%>`

### 5. Функции форматирования
Применяются к отдельным значениям (не являются агрегатами):
- `<%date(Дата создания, 'DD.MM.YYYY')%>` — форматирование даты.
- `<%now('DD.MM.YYYY HH:mm')%>` — текущие дата и время.
- `<%upper(Тема)%>`, `<%lower(Тема)%>`, `<%capitalize(Тема)%>` — изменение регистра.
- `<%truncate(Описание, 50)%>` — обрезка строки до 50 символов.
- `<%strip_html(Описание)%>` — удаление HTML-тегов.
- `<%nl2br(Описание)%>` — замена переносов строк на `<br>`.
- `<%replace(Тема, 'старое', 'новое')%>` — замена подстроки.
- `<%number(Оценка времени, 2)%>` — форматирование числа с 2 знаками после запятой.
- `<%default(Назначенный, 'Не назначен')%>` — значение по умолчанию, если поле пустое.
- `<%length(Тема)%>` — длина строки.
- `<%concat(Тема, ' (', ID, ')')%>` — объединение полей и строковых литералов (литералы в одинарных или двойных кавычках).

### 6. Метаданные выгрузки
- `<%ExportDate%>` — дата и время формирования документа.
- `<%ExportUser%>` — имя пользователя, запустившего выгрузку.
- `<%ProjectName%>` — название проекта.
- `<%QueryName%>` — название сохранённого запроса (если применяется).
- `<%FilterDescription%>` — текстовое описание применённых фильтров.

### 7. Нумерация
- `<%row_number%>` — глобальный порядковый номер основной записи (начинается с 1).
- `<%row_number_in_group%>` — номер записи внутри группы первого уровня.

## Ограничения и правила
1. Каждая агрегатная команда (например, `<%sum(Поле)%>`) может использоваться в шаблоне только **один раз**.
2. Переменная `<%count%>` допустима только внутри контекста группы (`GROUP_HEADER`/`GROUP_FOOTER`). Её использование вне этого контекста вызовет ошибку шаблона.
3. Маркеры `<%BEGIN_ROW%>` и `<%END_ROW%>` должны находиться в одной строке (для Excel) или логическом блоке (для Word).
4. Текст после `<%END_GROUPS%>` выводится только один раз в конце документа.

## Окно запуска формирования документов

При нажатии на кнопку экспорта открывается диалоговое окно, в котором можно настроить параметры генерации.

### Параметры экспорта
- **Файл шаблона**: обязательное поле для загрузки вашего файла `.docx` или `.xlsx`.
- **Режим экспорта**:
  - *Объединенный документ*: все задачи из выборки будут помещены в один файл (с учетом группировки, если она задана в шаблоне).
  - *Один документ на задачу*: для каждой задачи будет создан отдельный файл, а все файлы упакованы в ZIP-архив. К имени каждого файла будет добавлен ID задачи.
- **Имя файла**: базовое имя для сохраняемого документа или архива (без расширения). Запрещено использование символов `/:*?"<>|`.

### Настройки обработки
- **Формат описания**:
  - *Исходный текст*: вставляет текстовое содержимое поля описания без обработки.
  - *Как в Redmine*: преобразует вики-разметку и HTML-теги описания в форматированный вид. **Внимание:** эта опция доступна только для шаблонов Word (.docx). Для Excel всегда используется исходный текст.
- **Поведение при ошибках**:
  - *Прервать генерацию*: остановка процесса при первой же ошибке (например, отсутствующее поле или неверный синтаксис).
  - *Пропустить поле*: вместо значения ошибочного поля будет вставлена пустая строка, генерация продолжится.
  - *Пропустить задачу*: если в конкретной задаче возникает ошибка, она исключается из итогового документа, остальные задачи обрабатываются штатно.

### Информация и ранее созданные файлы
- В окне отображается количество задач в текущей выборке и ожидаемое количество файлов.
- В нижней части окна присутствует таблица **Доступные файлы**, где перечислены документы, сгенерированные вами ранее для этого проекта. Для каждого файла указано его имя, дата создания и автор.

### Хранение файлов
Сгенерированные файлы сохраняются на сервере во временной директории (`tmp/document_generator`). 
- Срок хранения файлов регулируется единственным параметром плагина (по умолчанию **24 часа**).
- По истечении этого срока файлы и их метаданные автоматически удаляются фоновым процессом при очередном открытии окна генерации.
- Срок "жизни" файла обновляется (продлевается) в момент успешного завершения его генерации.
